# Wiret

Wiret는 macOS 메뉴바에서 동작하는 간단한 음성 녹음 앱입니다. Dock 아이콘 없이 메뉴바 마이크 아이콘으로만 동작합니다.

## 기능

- 메뉴바에 쥐 아이콘 표시 (녹음 중에는 빨간색으로 바뀌고 왼쪽 아래에 녹음 점이 찍힘)
- 메뉴 항목
  1. **녹음 시작** (`⌘R`) — 유휴 상태에서만 활성화
  2. **녹음 중단** (`⌘S`) — 녹음 중일 때만 활성화
  3. **자동** — Google 캘린더 회의에 맞춘 자동 녹음 켜기/끄기 (체크마크로 상태 표시)
  4. **알림** — 회의 시작·종료 시각에 녹음 시작/중단을 묻는 알림 켜기/끄기 (체크마크로 상태 표시)
  5. **로그인 시 실행** — 맥에 로그인하면 Wiret을 자동으로 실행 (체크마크로 상태 표시, [로그인 시 실행](#로그인-시-실행) 참고)
  6. **캘린더** — 자동 녹음과 알림에 쓸 캘린더 선택 (하위 메뉴)
  7. **오늘의 일정** — 오늘 회의 목록과 자동 녹음·알림 제외 설정
  8. **업데이트 확인** — 같은 채널의 새 버전 확인 (메뉴를 닫지 않고 결과를 그 자리에 표시). 새 버전이 있으면 바로 아래에 **<버전>으로 업데이트** 항목이 생김
  9. 현재 버전 안내 문구 (비활성화된 항목, 예: "현재 버전: 0.0.11-SNAPSHOT", 로컬 빌드는 "현재 버전: 로컬 빌드 (자동 업데이트 꺼짐)")
  10. 자동 상태 안내 문구 (비활성화된 항목, 예: "자동: 꺼짐", "다음 회의: ...", "녹음 중: ...")
  11. **종료** (`⌘Q`) — 녹음 중이면 먼저 중단한 뒤 앱 종료
- 위 단축키는 메뉴가 열려 있는 동안에만 동작합니다.
- 녹음 중일 때는 "녹음 시작"이 비활성화되고, 유휴 상태일 때는 "녹음 중단"이 비활성화됩니다.

## 로그인 시 실행

메뉴의 **로그인 시 실행**을 켜면 맥에 로그인할 때 Wiret이 자동으로 실행됩니다. 기본값은 꺼짐입니다.

- 켜면 Wiret이 로그인 항목으로 등록되며, 시스템 설정 > 일반 > 로그인 항목에서도 확인할 수 있습니다.
- 자동 업데이트로 새 버전으로 바뀌어도 등록은 그대로 유지됩니다.
- macOS가 허용을 요구하면 시스템 설정의 로그인 항목이 열립니다. 목록에서 Wiret을 허용해주세요. 허용 전까지는 메뉴 항목에 `-` 표시가 붙습니다.
- 시스템 설정에서 직접 켜거나 끈 상태도 다음에 메뉴를 열 때 반영됩니다.

## 저장 위치

녹음 파일은 다음 경로에 저장됩니다.

```
~/Music/Wiret/Wiret-yyyyMMdd-HHmmss.m4a
```

자동 녹음으로 저장된 파일은 회의 제목이 파일명에 포함됩니다.

```
~/Music/Wiret/Wiret-yyyyMMdd-HHmmss-회의 제목.m4a
```

## 음성 메모 앱으로 보내기

메뉴의 **음성 메모로 보내기**를 켜면 녹음이 끝날 때마다 macOS 음성 메모 앱으로 자동으로 가져옵니다. 가져오기가 성공하면 `~/Music/Wiret`의 원본 파일은 삭제되고, 실패하면 원본이 그대로 남습니다.

### 단축어 설치

음성 메모 앱은 외부 앱이 파일을 직접 넣을 수 없습니다. 문서 타입도, URL 스킴도, AppleScript 사전도, 공유 확장도 없고 저장 폴더는 시스템이 보호합니다. 유일하게 열려 있는 길은 음성 메모의 **"녹음 가져오기" App Intent**이며, 이 동작은 단축어를 통해서만 호출할 수 있습니다.

게다가 이 동작은 인텐트 정의에 `isDiscoverable: false`로 표시돼 있어 **단축어 앱의 동작 목록에서 검색되지 않습니다.** 손으로는 만들 수 없다는 뜻입니다. 그래서 Wiret이 동작 식별자를 직접 적은 단축어를 만들어 서명한 뒤 단축어 앱에 넘깁니다.

메뉴에서 **음성 메모 단축어 설치**를 누르면:

1. Wiret이 `com.apple.VoiceMemos.RCImportRecording` 동작을 담은 단축어 파일을 만듭니다.
2. `shortcuts sign`으로 서명합니다.
3. 단축어 앱이 열리면 **단축어 추가**를 누르면 끝입니다.

이미 설치돼 있으면 같은 자리에 **음성 메모 단축어 삭제**가 대신 보입니다. 다만 macOS는 앱이 단축어를 직접 지우는 것을 허용하지 않아, 단축어 앱에서 해당 단축어를 열어주는 것까지만 하고 삭제(⌘⌫)는 사용자가 마무리해야 합니다.

**자동** 녹음을 켤 때 단축어가 없으면 설치를 자동으로 띄웁니다.

설치 여부는 아래로 확인할 수 있습니다.

```bash
shortcuts list | grep "Wiret 음성 메모 가져오기"
```

### 동작 규칙

- 단축어가 없는 상태에서 **음성 메모로 보내기**를 켜면 단축어 설치를 먼저 띄우고, 사용자가 단축어 앱에서 추가를 끝낼 때까지는 켜지지 않습니다. "켜짐"이 곧 "동작함"이어야 하기 때문입니다.
- 메뉴를 열 때마다 단축어 설치 여부를 다시 확인합니다. 단축어는 Wiret 밖에서도 추가·삭제되기 때문입니다.
- 켜져 있다가 단축어가 사라지면, 실패가 반복되지 않도록 설정이 자동으로 꺼집니다.
- 0바이트 녹음(시작하자마자 끊긴 경우)은 가져오지 않습니다.
- **원본 삭제는 가져오기가 성공했을 때만** 일어납니다. 실패하면 녹음은 `~/Music/Wiret`에 남습니다.
- 앱을 종료해 녹음이 끝나는 경우에는, 프로세스가 사라지기 전에 끝나도록 가져오기를 동기로 실행합니다.

## 자동 녹음 (Google 캘린더)

Wiret 메뉴의 **자동**을 켜면 macOS 캘린더 앱에 등록된 Google 캘린더 회의 시간에 맞춰 자동으로 녹음을 시작·중단합니다.

### 사용 방법

1. 시스템 설정 > 인터넷 계정 > Google 계정을 추가하고 **캘린더** 항목을 체크해 macOS 캘린더 앱에서 Google 캘린더를 볼 수 있게 합니다.
2. Wiret 메뉴에서 **자동**을 켭니다.
3. 처음 켤 때 캘린더 접근 권한을 요청하며, 허용하면 자동 녹음이 시작됩니다.

### 캘린더 선택

메뉴의 **캘린더** 하위 메뉴에서 자동 녹음에 쓸 캘린더를 고를 수 있습니다. 여러 개를 동시에 고를 수 있고, 선택은 앱을 다시 켜도 유지됩니다.

- **자동 (Google 캘린더)** — 기본값입니다. Google 캘린더를 대상으로 하고, Google 소스가 없으면 전체 캘린더를 봅니다.
- 캘린더를 하나라도 고르면 그 캘린더만 봅니다. 고른 항목을 다시 누르면 선택이 풀리고, 전부 풀면 자동으로 돌아갑니다.
- 이름이 같은 캘린더가 여러 계정에 있을 수 있어, 항목 위에 마우스를 올리면 계정 이름이 표시됩니다.
- 계정이 삭제되어 골라 둔 캘린더가 모두 사라지면 자동 규칙으로 되돌아갑니다. 아무것도 못 보는 상태로 조용히 멈추지 않게 하기 위해서입니다.
- 계정 추가·삭제가 반영되도록 메뉴를 열 때마다 캘린더 목록을 다시 읽습니다.

### 오늘의 일정

메뉴의 **오늘의 일정**을 누르면 선택한 캘린더의 오늘 회의를 시간과 함께 보여줍니다.

```
9월 16일 (화)
체크된 회의가 자동 녹음·알림 대상입니다. 녹음하고 싶지 않은 회의는 체크를 끄세요.

☑ 09:30–09:45   데일리 스크럼
☑ 11:00–12:00   Agent Builder 주간 회의
☐ 12:30–13:00   점심 - 팀 1on1
☑ 15:00–16:30   Wiret 스펙 리뷰
```

- **기본은 모두 포함**입니다. 새로 생긴 회의도 손대지 않으면 자동 녹음 대상이 됩니다.
- 체크를 끄면 그 회의만 자동 녹음과 회의 알림에서 빠집니다. 다시 켜면 되돌아옵니다.
- 지금 녹음 중인 회의의 체크를 끄면 곧바로 녹음이 중단됩니다.
- 겹친 회의 중 하나를 빼 두면 선택 창이 뜨지 않고 남은 회의가 바로 녹음됩니다.
- 제외한 회의 때문에 잠자기를 막지 않습니다.
- 제외 기록은 회의 시작 시각과 함께 저장되어, 지난 것은 앱을 실행할 때 정리됩니다. 반복 일정은 회차마다 식별자가 달라 기록이 계속 쌓이기 때문입니다.

### 음성 메모가 녹음 중일 때

음성 메모 앱으로 직접 녹음하고 있는 동안에는 Wiret이 끼어들지 않습니다. 자동 녹음도, 자동 중단도 하지 않고, 겹친 회의 선택 창이 떠 있었다면 닫습니다. 사용자가 직접 시작한 녹음이 우선이기 때문입니다.

이때 메뉴의 상태 문구는 `자동: 음성 메모가 녹음 중이라 대기`로 바뀝니다. 음성 메모 녹음이 끝나면 다음 확인(10초 주기)에서 평소대로 동작합니다.

판별은 CoreAudio의 프로세스 목록에서 `com.apple.VoiceMemos`의 입력 사용 여부(`kAudioProcessPropertyIsRunningInput`)를 읽어서 합니다. 마이크를 쓰는 아무 앱이나 막지 않고 음성 메모만 보는 이유는, 화상 회의 앱까지 막으면 정작 녹음이 가장 필요한 회의 중에 자동 녹음이 멈추기 때문입니다.

이 CoreAudio API는 macOS 14.2에서 들어왔습니다. 더 낮은 버전에서는 조회가 실패하고, 그때는 "감지되지 않음"으로 떨어져 기존 동작을 그대로 유지합니다.

### 동작 규칙

- 회의가 시작되면 자동으로 녹음을 시작하고, 회의가 끝나면 자동으로 녹음을 중단합니다. 단, **알림**이 켜져 있으면 회의가 끝날 때 멈추지 않고 종료 알림으로 묻습니다([자동 녹음과 함께 쓸 때](#자동-녹음과-함께-쓸-때)).
- 자동으로 시작된 녹음 파일명에는 회의 이름이 포함됩니다.
- 수동으로 녹음 중일 때는 자동 녹음이 개입하지 않습니다.
- 사용자가 수동으로 중단한 회의는 같은 회의가 진행 중이더라도 자동으로 재시작하지 않습니다.
- 종일 일정, 취소된 일정, 참석을 거절한 일정은 자동 녹음 대상에서 제외됩니다.
- 캘린더를 직접 고르지 않았고 Google 소스로 표시되는 캘린더도 없으면, macOS 캘린더 앱의 전체 캘린더를 대상으로 확인합니다.
- 회의 일정은 10초 주기로 다시 확인합니다.
- 잠자기에서 깨어나면 즉시 회의 상태를 다시 확인합니다.
- 캘린더 접근 권한이 거부되면 자동 항목이 다시 꺼지고 권한 안내창이 표시됩니다.

### 겹치는 회의

같은 시간에 회의가 두 개 이상 진행 중일 때는 Wiret이 임의로 고르지 않고 **겹치는 회의 선택** 창을 띄웁니다.

- 창에는 진행 중인 회의가 `회의 제목  HH:mm–HH:mm` 형식으로 나열되며, 하나를 고르고 **녹음 시작**을 누르면 그 회의를 녹음합니다.
- **건너뛰기**(또는 창 닫기)를 누르면 그 시간대에 겹친 회의들은 모두 자동 녹음 대상에서 제외됩니다.
- 이미 자동 녹음 중일 때 다른 회의가 겹쳐 시작해도 진행 중인 녹음은 중단되지 않습니다.
- 녹음하던 회의가 먼저 끝나고 겹쳐 있던 회의가 아직 진행 중이면, 그 회의의 녹음을 이어서 시작합니다.
- 선택을 기다리는 동안 겹친 회의가 하나만 남으면 선택 창은 자동으로 닫히고 남은 회의가 바로 녹음됩니다.

### 덮개를 닫아도 계속 녹음되나요?

Wiret은 회의 시작 30분 전부터 회의가 끝날 때까지 시스템 유휴 잠자기(idle sleep)를 막는 전원 어설션(power assertion)을 유지합니다. 따라서 자리를 비워도 화면 잠금 시간 때문에 녹음이 끊기지 않습니다.

다만 macOS는 MacBook 덮개를 닫으면 (외장 디스플레이와 전원 어댑터가 연결된 경우를 제외하고) 강제로 잠자기에 들어가며, 이때 마이크 입력도 중단됩니다. 전원 어설션으로도 이 동작은 막을 수 없습니다. 덮개를 닫은 상태로 녹음하려면 **외장 디스플레이 + 전원 어댑터를 연결**하거나 **덮개를 열어 두어야** 합니다.

잠자기에서 깨어나면 Wiret은 즉시 회의 상태를 다시 확인해, 자는 동안 끝난 회의는 바로 중단하고 그 사이에 시작된 회의는 바로 녹음을 시작합니다.

## 회의 알림

메뉴의 **알림**을 켜면 캘린더 회의 시각에 맞춰 녹음을 할지 묻는 알림을 띄웁니다. 자동 녹음과 달리 Wiret이 스스로 녹음을 시작하거나 끝내지 않고, 결정은 알림에서 사용자가 합니다. 처음 켤 때 캘린더 접근 권한을 요청하며, 거부되면 알림 항목이 다시 꺼지고 권한 안내창이 표시됩니다.

- **회의 시작 알림** — 회의 시작 시간이 되면 `회의 제목`과 `HH:mm–HH:mm 회의가 시작됐습니다. 녹음을 시작할까요?`를 보여줍니다.
  - **녹음 시작** — 회의 제목이 들어간 파일명으로 녹음을 시작합니다.
  - **취소** (또는 창 닫기) — 그 회의로는 다시 묻지 않습니다.
- **회의 종료 알림** — **녹음 중일 때만**, 녹음하던 회의의 종료 시간이 되면 뜹니다. 알림에서 시작한 녹음뿐 아니라 메뉴에서 직접 시작한 녹음도 회의 중이었다면 대상입니다.
  - **지금 종료** — 바로 녹음을 중단합니다.
  - **몇 분 후 종료** — 5·10·15·30분 중에 고르면 그만큼 뒤에 녹음을 중단합니다. 그 사이 직접 녹음을 멈추면 예약도 함께 사라집니다.
  - **취소** (또는 창 닫기) — 녹음을 그대로 이어 갑니다. 같은 회의로는 다시 묻지 않습니다.
- 알림은 시스템 알림처럼 화면 오른쪽 위에 떠 있는 작은 창으로 뜨고, 소리와 함께 답할 때까지 사라지지 않습니다. 전체 화면으로 띄운 화상 회의 앱 위에도 보입니다.
- 알림이 떠도 입력 중인 앱의 포커스를 빼앗지 않습니다. 채팅에 치던 Return이 알림 버튼을 누르지 않도록, 알림 창을 한 번 클릭한 뒤에야 Return/Esc가 동작합니다.
- 알림은 한 번에 하나만 뜹니다. 같은 시간에 회의가 여럿 시작되면 하나에 답한 뒤 다음 회의를 묻습니다.
- 알림이 떠 있는 사이 상황이 바뀌면(회의가 끝남, 다른 경로로 녹음이 시작되거나 끝남) 알림은 저절로 닫힙니다.
- **알림**을 끄면 예약해 둔 **몇 분 후 종료**도 함께 취소됩니다. 녹음은 계속되므로 직접 **녹음 중단**을 눌러야 합니다.

### 자동 녹음과 함께 쓸 때

- **자동**이 켜져 있으면 회의 시작은 자동 녹음이 맡으므로 시작 알림은 뜨지 않습니다.
- 자동으로 시작된 녹음도 회의가 끝나면 바로 멈추지 않고 **회의 종료 알림**을 띄웁니다. 회의가 길어졌을 때 녹음이 끊기지 않게 직접 끝낼 시점을 고를 수 있습니다. 답하지 않으면 녹음은 계속됩니다.
  - 연달아 잡힌 다음 회의는 이 녹음이 끝난 뒤(지금 종료 또는 몇 분 후 종료) 자동으로 녹음이 시작됩니다. **취소**로 녹음을 이어 가면 다음 회의는 그 녹음에 이어서 담기고, 다음 회의가 끝날 때 다시 묻습니다.
- 다만 녹음 중인 회의를 **오늘의 일정**에서 빼거나 캘린더에서 지웠을 때, 그리고 **자동**을 껐을 때는 묻지 않고 바로 멈춥니다.
- **알림**이 꺼져 있으면 예전처럼 자동이 회의가 끝날 때 녹음을 멈춥니다.
- **오늘의 일정**에서 체크를 끈 회의는 녹음하고 싶지 않은 회의이므로 알림도 뜨지 않습니다.
- 음성 메모 앱으로 직접 녹음 중일 때는 시작 알림을 띄우지 않습니다.

## 자동 업데이트

Wiret은 실행할 때와 6시간마다 새 버전을 확인하고, 있으면 알려 줍니다. **지금 업데이트**를 누르면 내려받아 교체한 뒤 다시 실행합니다. 메뉴의 **업데이트 확인**으로 직접 확인할 수도 있습니다.

### 메뉴에서 확인하기

**업데이트 확인**을 눌러도 메뉴는 닫히지 않습니다. 확인하는 동안 항목이 "업데이트 확인 중…"으로 바뀌고, 끝나면 결과가 그 자리에 나타납니다. 창은 뜨지 않습니다.

| 결과 | 항목 문구 |
| --- | --- |
| 최신 | "최신 버전입니다" (다시 눌러 확인할 수 있음) |
| 실패 | "업데이트 확인 실패 · 다시 시도" (마우스를 올리면 이유가 보임) |
| 새 버전 있음 | "업데이트 확인" 그대로, 바로 아래에 **<버전>으로 업데이트** 항목이 생김 |

- **<버전>으로 업데이트** 항목은 더 새 버전이 있을 때만 보입니다. 누르면 메뉴가 닫히고 내려받기를 시작하며, 그동안 "업데이트 내려받는 중…"으로 바뀝니다. 실패하면 이유를 알리고 다시 누를 수 있게 돌아옵니다.
- 자동 확인이 새 버전을 찾으면 지금처럼 창으로 묻고, 같은 항목도 메뉴에 만들어 둡니다. 창에서 **나중에**를 눌러도 메뉴에서 언제든 업데이트할 수 있습니다.
- 확인 결과 문구는 다음에 메뉴를 열면 "업데이트 확인"으로 돌아갑니다. 오래전의 "최신 버전입니다"가 지금도 최신이라는 뜻으로 읽히지 않게 하려는 것입니다.

### 채널은 섞이지 않습니다

| 지금 쓰는 버전 | 업데이트 대상 |
| --- | --- |
| `0.0.7-SNAPSHOT` | `0.0.8-SNAPSHOT`, `0.1.0-SNAPSHOT` … (스냅샷만) |
| `1.0.0` | `1.0.1`, `1.1.0` … (정식만) |

스냅샷 사용자에게 정식 버전을 주면 검증 중인 변경을 잃고, 정식 사용자에게 스냅샷을 주면 안정 버전이 아니게 됩니다. 그래서 두 채널은 서로를 보지 않습니다.

새 버전 목록은 GitHub Releases API에서 읽고, 실패하면 릴리스 Atom 피드로 한 번 더 시도합니다. 익명 API는 IP당 시간 60회로 묶여 있어 회사망처럼 여러 사람이 같은 공인 IP를 쓰면 남의 호출 때문에 403이 나기 때문입니다. 피드에는 자산 목록이 없어 내려받을 주소를 CI의 이름 규칙(`Wiret-<버전>.zip`)에서 만들고, 설치 직전 버전 확인으로 잘못 짚은 경우를 걸러냅니다.

판단 기준은 `Info.plist`의 `WiretVersion` 값입니다. `build_app.sh`가 배포 빌드에 써 넣으며, 이 값이 없는 로컬 빌드는 채널을 알 수 없으므로 업데이트를 제안하지 않습니다. 이때 메뉴에는 "현재 버전: 로컬 빌드 (자동 업데이트 꺼짐)"이 표시되며, 자동 업데이트를 받으려면 릴리스 zip을 `/Applications`에 설치해야 합니다.

### 동작 규칙

- 녹음 중에는 자동 확인이 말을 걸지 않습니다. 앱을 교체하면 녹음이 끊기기 때문입니다. 직접 **업데이트 확인**을 누른 경우는 사용자의 의도이므로 진행합니다.
- **나중에**를 누른 버전은 그 실행 동안 다시 묻지 않습니다. 더 새 버전이 나오면 다시 묻습니다.
- 자동 확인이 실패하면(네트워크 문제 등) 조용히 넘어갑니다. 직접 눌렀을 때만 메뉴 항목에 실패를 표시합니다.
- 내려받은 앱의 `WiretVersion`이 기대한 버전과 다르면 교체하지 않습니다. 엉뚱한 파일로 앱을 덮어쓰면 복구가 어렵습니다.

## 다운로드 (정식 버전)

- 최신 정식 버전: <https://github.com/hanoseok/Wiret/releases/latest>
- 직접 받기: `https://github.com/hanoseok/Wiret/releases/download/v1.0.0/Wiret-1.0.0.zip`

정식 버전을 설치하면 이후 정식 버전 안에서만 자동으로 업데이트됩니다.

## 다운로드 (스냅샷 빌드)

`develop` 브랜치에 푸시되면 GitHub Actions가 자동으로 `x.y.z-SNAPSHOT` 버전을 빌드해 릴리스로 올립니다. (`0.0.1-SNAPSHOT`부터 시작하고, 푸시될 때마다 패치 번호가 1씩 올라갑니다.)

- 항상 최신 스냅샷: <https://github.com/hanoseok/Wiret/releases/download/snapshot-latest/Wiret-snapshot.zip>
- 버전별 스냅샷: <https://github.com/hanoseok/Wiret/releases>

```bash
curl -L -o Wiret-snapshot.zip \
  https://github.com/hanoseok/Wiret/releases/download/snapshot-latest/Wiret-snapshot.zip
unzip Wiret-snapshot.zip
mv Wiret.app /Applications/
xattr -dr com.apple.quarantine /Applications/Wiret.app
open /Applications/Wiret.app
```

압축을 풀면 바로 실행할 수 있는 `Wiret.app`이 나옵니다. Apple 개발자 인증서로 서명·공증한 앱이 아니라, 내려받은 뒤 첫 실행 전에 위처럼 격리 속성(`com.apple.quarantine`)을 제거해야 합니다. 스냅샷 빌드는 Apple Silicon과 Intel을 모두 지원하는 universal 바이너리입니다.

## 아이콘

메뉴 막대 아이콘과 앱 아이콘 모두 [`Sources/Wiret/MouseIcon.swift`](Sources/Wiret/MouseIcon.swift)에서 베지어 패스로 그립니다. 이미지 파일을 두지 않아 18pt부터 1024pt까지 같은 도형을 선명하게 씁니다.

- **메뉴 막대**: 템플릿 이미지라 라이트/다크 메뉴 막대에 자동으로 맞춰집니다. 18pt에서 뭉개지는 꼬리와 코는 빼고 얼굴만 그립니다. 녹음 중에는 빨간색 + 녹음 점으로 바뀌어, 색을 구분하기 어려운 환경에서도 상태를 알 수 있습니다.
- **앱 아이콘**: 둥근 사각형 바탕에 꼬리까지 그린 컬러 버전입니다. `build_app.sh`가 빌드할 때마다 같은 코드로 10종 크기를 만들어 `AppIcon.icns`로 묶습니다.

## 빌드 방법

```bash
./build_app.sh
```

`Package.swift` 기준으로 release 빌드를 수행하고, `build/Wiret.app` 번들을 생성한 뒤 코드사이닝을 적용합니다. 서명 인증서를 지정하지 않으면 ad-hoc으로 서명합니다. 배포 빌드(CI)는 항상 인증서로 서명합니다. 자세한 내용은 [코드 서명](#코드-서명)을 참고하세요.

다음 환경 변수로 동작을 바꿀 수 있습니다. (CI 스냅샷 빌드가 사용하는 값입니다.)

| 환경 변수 | 설명 |
| --- | --- |
| `UNIVERSAL=1` | arm64 + x86_64 universal 바이너리로 빌드 |
| `MARKETING_VERSION=x.y.z` | `CFBundleShortVersionString` 덮어쓰기 |
| `BUILD_NUMBER=n` | `CFBundleVersion` 덮어쓰기 |
| `SIGN_IDENTITY=...` | 서명 인증서 이름 또는 SHA-1 (없으면 ad-hoc) |
| `SIGN_KEYCHAIN=path` | `SIGN_IDENTITY`를 찾을 키체인 |

```bash
UNIVERSAL=1 MARKETING_VERSION=0.0.1 BUILD_NUMBER=1 ./build_app.sh
```

## 마이크 권한 안내

처음 "녹음 시작"을 누르면 마이크 접근 권한을 요청합니다. 만약 권한이 거부된 상태라면 안내창의 "시스템 설정 열기" 버튼을 눌러 **시스템 설정 > 개인정보 보호 및 보안 > 마이크**에서 Wiret의 접근을 허용해주세요.

배포 빌드는 같은 인증서로 서명되므로 업데이트해도 마이크·캘린더 권한이 유지됩니다. 반면 직접 빌드한 `build/Wiret.app`은 ad-hoc으로 서명되어 다시 빌드할 때마다 권한을 다시 요청하고, 배포 빌드와도 서로 다른 앱으로 취급됩니다.

## 아이콘이 보이지 않을 때

macOS는 메뉴 막대가 가득 차면 새 아이콘을 노치 뒤로 숨깁니다. Wiret을 실행했는데 메뉴 막대에 아이콘이 보이지 않는다면, 다른 메뉴 막대 아이콘을 제거하거나(⌘ 키를 누른 채 메뉴 막대 밖으로 드래그) Ice, Bartender 같은 메뉴 막대 관리 앱을 사용하면 Wiret 아이콘이 표시됩니다. Wiret은 아이콘이 숨겨진 상태에서도 계속 실행되며, 아이콘이 다시 나타나면 바로 사용할 수 있습니다.

## 코드 서명

macOS는 캘린더·마이크 권한을 앱의 **서명 요구사항**에 묶어 기억합니다. ad-hoc 서명은 이 요구사항이 빌드마다 바뀌는 해시(`cdhash`)라서, 업데이트할 때마다 권한이 초기화됩니다. 캘린더 권한이 없으면 자동 녹음도 스스로 꺼집니다.

그래서 CI는 모든 배포 빌드를 같은 자체 서명 인증서(`Wiret Code Signing (hanoseok)`)로 서명합니다. 그러면 서명 요구사항이 빌드와 상관없이 같아집니다.

```
designated => identifier "com.hanoseok.wiret" and certificate root = H"4dbaa1aa81c3e94b4bd0484c3e3739790bd5c028"
```

- 인증서는 저장소 시크릿 `WIRET_SIGNING_P12_BASE64`(base64로 인코딩한 .p12)와 `WIRET_SIGNING_P12_PASSWORD`로 CI에 전달됩니다. `Scripts/setup_signing_keychain.sh`가 이를 임시 키체인에 넣습니다.
- 시크릿이 없으면 빌드는 ad-hoc으로 넘어가지 않고 **실패**합니다. 빌드 뒤 "서명 확인" 단계도 인증서 서명이 아니면 실패합니다. ad-hoc 빌드가 배포되면 사용자 권한이 초기화되기 때문입니다.
- 인증서를 **바꾸거나 잃어버리면** 서명 요구사항이 달라져, 모든 사용자의 권한이 한 번 초기화됩니다. 원본 .p12는 저장소 밖에 보관합니다.
- Apple 공증을 받은 인증서가 아니므로 Gatekeeper 확인을 피하지는 못합니다. 설치 방법은 [다운로드 (스냅샷 빌드)](#다운로드-스냅샷-빌드)의 안내를 따르세요.

## 정식 릴리스 (CI)

`.github/workflows/release.yml`이 `v1.0.0` 처럼 **`-SNAPSHOT`이 없는 태그**를 푸시하면 정식 릴리스를 만듭니다.

```bash
git tag v1.0.0 && git push origin v1.0.0
```

테스트 → universal 빌드 → `Info.plist`에 기록된 채널 확인 → 압축 → 릴리스 생성 순서로 동작합니다. 채널 확인 단계를 둔 이유는, 여기에 `-SNAPSHOT`이 섞이면 정식 사용자가 스냅샷으로 갱신되기 때문입니다.

`workflow_dispatch`로 버전을 직접 넣어 실행할 수도 있습니다.

## 스냅샷 릴리스 (CI)

`.github/workflows/snapshot.yml`이 `develop` 브랜치 푸시마다 아래 순서로 동작합니다.

1. 기존 `v*.*.*-SNAPSHOT` 태그 중 가장 높은 버전을 찾아 패치 번호를 1 올립니다. (태그가 없으면 `0.0.1`)
2. `swift test`로 테스트를 돌립니다.
3. universal `Wiret.app`을 빌드하고 버전 정보를 `Info.plist`에 기록합니다.
4. `ditto`로 앱 번들을 압축합니다.
5. `vx.y.z-SNAPSHOT` 태그로 프리릴리스를 만들고, `snapshot-latest` 릴리스를 최신 빌드로 교체합니다.

`workflow_dispatch`로 수동 실행도 할 수 있습니다.
